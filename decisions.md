# Decisions

Project decisions, permanent IDs. A reversed decision is marked
`superseded by DEC-NNNN`, never deleted.

| ID | Date | Decision | Decided by | Source |
|---|---|---|---|---|
| DEC-0001 | 2026-10-19 | The delivery note's 280-character limit counts Unicode characters (code points) of the note after trimming; a line break counts as one character. orders-service rejects an order whose note is longer with a validation error (HTTP 400) and creates no order; it never truncates the note. The client may still change this. *Amended by DEC-0008.* | kb-synthesizer (default) | LIN-GTB-2 (Q-0002) |
| DEC-0002 | 2026-10-19 | orders-service trims leading and trailing whitespace from the delivery note; a note that is empty or only whitespace is stored as no note. Line breaks inside the note are kept. An order without a note returns `deliveryNote` as `null`, and orders placed before the note existed have no note. The client may still change this. | kb-synthesizer (default) | LIN-GTB-2 (Q-0002) |
| DEC-0003 | 2026-10-19 | The note field in the web order form and the app's order screen accepts at most 280 characters (further typing or pasted text beyond 280 is not taken in); no character counter is required. The client may still change this. *Amended by DEC-0008.* | kb-synthesizer (default) | LIN-GTB-2 |
| DEC-0004 | 2026-10-19 | "Can't be changed after the order is placed" means: orders-service offers no way to set or change the note of an existing order, every other order operation (such as cancelling) leaves the note as it was, and neither the web shop nor the app offers a way to edit it. The client may still change this. | kb-synthesizer (default) | LIN-GTB-2 |
| DEC-0005 | 2026-10-19 | The web order list shows, for an order with a note, a note icon with an accessible, localized label saying the order has a delivery note, and nothing for an order without one; the list does not show the note's text. The client may still change this. | kb-synthesizer (default) | LIN-GTB-2 |
| DEC-0006 | 2026-10-19 | The app shows the full text of an order's delivery note on that order in My orders, and nothing for an order without one. The client may still change this. | kb-synthesizer (default) | LIN-GTB-2 |
| DEC-0007 | 2026-10-19 | "The warehouse sees" the note through the order as orders-service returns it; no warehouse screen, label printing or other warehouse integration is in scope for LIN-GTB-2. The client may still change this. | kb-synthesizer (default) | LIN-GTB-2 (Q-0001) |
| DEC-0008 | 2026-10-19 | The web order form and the app's order screen count the note's 280 characters in the same unit as orders-service (DEC-0001): Unicode code points of the note after trimming, so a character made of several code points (such as a family emoji) counts as several at both ends. A Windows line break (CR LF) is normalised to one line feed (LF) before trimming and counting, by the web shop and the app in the field and by orders-service on receipt, so a line break always counts as one character. Amends DEC-0001 and DEC-0003. The client may still change this. | kb-synthesizer (default) | LIN-GTB-2 (Q-0002) |
| DEC-0009 | 2026-10-19 | When orders-service rejects an order because of its note (validation error, HTTP 400, FR-0001.AC-3), the web shop and the app place no order, show the error at the note field in the user's language, and keep everything the customer entered, including the note, so they can shorten it and place the order again. The client may still change this. | kb-synthesizer (default) | LIN-GTB-2 |
