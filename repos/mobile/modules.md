# mobile — modules

*Written by the onboarder from the repository at its `main`. The repository is
one Flutter package, `shopfront_mobile` (`pubspec.yaml:1`); its parts are
folders under `lib/`, plus tests, tooling and the two platform projects.*

Dependency direction, from the imports: screens → state, data, util, generated
DTOs; data → generated clients, config; state → generated DTOs; app → screens,
state, data; main → app, config, data.

## App shell (`lib/main.dart`, `lib/app.dart`, `lib/config.dart`)

What it does: starts the app, builds the configuration and the HTTP
repository, and shows three tabs: Products, Order, My orders
(`lib/app.dart:59-79`). Switching tabs hides the current snackbar so it
doesn't cover the order button (`lib/app.dart:43-47`); the Order tab shows a
badge with the cart's item count (`lib/app.dart:67-73`). After an order is
placed the shell switches to My orders (`lib/app.dart:54`).

Main files: `lib/main.dart`, `lib/app.dart`, `lib/config.dart`.

Depends on: `provider`, `flutter/material`, `lib/data/`, `lib/screens/`,
`lib/state/cart.dart`.

## Data (`lib/data/`)

What it does: `ShopRepository` is the interface the screens use: fetch
products (optional search query), place an order from order lines, fetch the
customer's orders, cancel an order (`lib/data/shop_repository.dart:6-14`).
`ApiShopRepository` implements it over the generated clients: products page
0 of size 50 from the catalog; orders page 0 of size 50 for the configured
customer; cancel with the fixed reason `Cancelled in the app`
(`lib/data/api_shop_repository.dart:27-53`).

Main files: `lib/data/shop_repository.dart`,
`lib/data/api_shop_repository.dart`.

Depends on: `dio`, `lib/api/generated/catalog/`, `lib/api/generated/orders/`,
`lib/config.dart`.

## Generated API clients (`lib/api/generated/`)

What it does: typed HTTP clients and DTOs for the two backend services,
generated by `swagger_parser` from `openapi/*.json`, with `retrofit` for the
calls and `json_serializable` for the models (`swagger_parser.yaml`).

- `orders/`: `OrdersClient` with `listOrders`, `createOrder`, `getOrder`,
  `cancelOrder`, `markShipped` under `/api/v1/orders`
  (`lib/api/generated/orders/orders/orders_client.dart:16-49`); models
  `CreateOrderRequest`, `OrderLineRequest`, `CancelOrderRequest`,
  `OrderResponse`, `OrderLineResponse`, `OrderSummaryDto`,
  `PageResponseOrderSummaryDto`, and the enums `Status`,
  `OrderResponseStatus`, `OrderSummaryDtoStatus`
  (`lib/api/generated/orders/export.dart`).
- `catalog/`: `ProductsClient` with `search`, `create`, `getApiProductsId`,
  `update`, `prices`, `addPrice` under `/api/products`
  (`lib/api/generated/catalog/products/products_client.dart:17-57`);
  `CategoriesClient` with `list`, `create1` under `/api/categories`
  (`lib/api/generated/catalog/categories/categories_client.dart:12-21`);
  models `ProductResponse`, `ProductPage`, `Money`, `PriceResponse`,
  `CategoryDto`, `CreateProductRequest`, `UpdateProductRequest`,
  `CreatePriceRequest`, `ErrorResponse`
  (`lib/api/generated/catalog/export.dart`).

The app uses only `ProductsClient.search`, `OrdersClient.listOrders`,
`createOrder` and `cancelOrder` (`lib/data/api_shop_repository.dart`). The
rest is generated because it is in the spec.

Main files: `lib/api/generated/orders/export.dart`,
`lib/api/generated/catalog/export.dart`, and the `.g.dart` parts next to each
file.

Depends on: `dio`, `retrofit`, `json_annotation`; at generation time
`swagger_parser`, `build_runner`, `retrofit_generator`, `json_serializable`
(`pubspec.yaml:37-55`).

## Cart state (`lib/state/cart.dart`)

What it does: the order being built. `CartLine` is a product with a
quantity; `Cart` adds a line per `add` (no merging), sets a line's quantity
(zero removes it), clears, and converts to `OrderLineRequest`s
(`lib/state/cart.dart:6-53`). Exposes `itemCount`, `total` and the currency
of the first line (`lib/state/cart.dart:22-27`).

Main files: `lib/state/cart.dart`.

Depends on: `flutter/foundation` (`ChangeNotifier`), generated DTOs
`ProductResponse`, `OrderLineRequest`.

## Screens (`lib/screens/`)

- **Products** (`products_screen.dart`): loads the product list once, shows
  name (falls back to SKU) and price, an add-to-cart button disabled when the
  product has no price, pull-to-refresh, and an error view with Retry
  (`lib/screens/products_screen.dart:16-113`).
- **Create order** (`create_order_screen.dart`): the cart's lines with
  quantity steppers, the total, a Place order button that disables while
  submitting, an inline error line, and a snackbar `Order #<id> placed`;
  clears the cart and calls `onOrderPlaced` on success
  (`lib/screens/create_order_screen.dart:18-131`).
- **My orders** (`my_orders_screen.dart`): the customer's orders with item
  count, status label and total; a cancel button only for `PLACED` orders,
  behind a confirmation dialog; reloads after cancelling
  (`lib/screens/my_orders_screen.dart:15-126`).

Depends on: `provider`, `lib/data/shop_repository.dart`,
`lib/state/cart.dart`, `lib/util/money.dart`, generated DTOs; the create
order screen also imports `dio` for `DioException`
(`lib/screens/create_order_screen.dart:1`).

## Util (`lib/util/money.dart`)

What it does: `formatMoney(amount, currency)`: two decimals, `€`/`$`/`£`
prefix for EUR/USD/GBP, otherwise `<value> <CODE>`, and `–` for a null
amount (`lib/util/money.dart:1-10`).

Depends on: nothing.

## Tests (`test/`, `integration_test/`)

- `test/state/cart_test.dart`: three unit tests of `Cart`.
- `test/util/money_test.dart`: three unit tests of `formatMoney`.
- `test/widget/screens_test.dart`: eight widget tests of the whole app
  against `FakeShopRepository`; one is skipped
  (`test/widget/screens_test.dart:82-89`).
- `test/support/fake_shop_repository.dart`: the in-memory backend with three
  default products, a `failProducts` switch, and a record of placed lines.
- `integration_test/order_flow_test.dart`: one device test, fake backend by
  default, real backend with `E2E_BACKEND=true`.

Depends on: `flutter_test`, `integration_test` (`pubspec.yaml:43-57`).

## Generator tooling (`tool/`, `swagger_parser.yaml`, `openapi/`)

What it does: `tool/generate_api.sh` runs `dart run swagger_parser`,
`dart run build_runner build --delete-conflicting-outputs`, then
`dart format lib/api/generated` (`tool/generate_api.sh:7-9`).
`swagger_parser.yaml` maps `openapi/orders.json` to
`lib/api/generated/orders` and `openapi/catalog.json` to
`lib/api/generated/catalog`, with `json_serializable`, no root client,
`unknown_enum_value: true` and files marked as generated
(`swagger_parser.yaml:5-16`). The specs come from the services' CI artifacts
or local builds (`README.md:32-34`).

## Platform projects (`android/`, `ios/`)

- **Android**: namespace and application id
  `com.shopfront.shopfront_mobile`, Java 17, SDK versions from the Flutter
  plugin, release build signed with the debug key for now
  (`android/app/build.gradle.kts:7-35`). Label `Shopfront`, `INTERNET`
  permission (`android/app/src/main/AndroidManifest.xml:2-4`); cleartext
  traffic allowed in debug only (`android/app/src/debug/AndroidManifest.xml`).
- **iOS**: display name `Shopfront Mobile`, local networking allowed, iOS
  15.0 (`ios/Runner/Info.plist:9-10,52-56`,
  `ios/Runner.xcodeproj/project.pbxproj:363`); simulator builds arm64 only
  (`ios/Flutter/Debug.xcconfig`). `ios/RunnerTests/` holds the template's
  empty XCTest.

## CI (`.github/workflows/ci.yml`)

Job `test` on Ubuntu: `flutter pub get`, regenerate the client and fail on a
diff, `flutter analyze`, `flutter test`. Then `android` (debug APK uploaded as
artifact `app-debug-apk`) and `ios` on macOS (debug build, no code signing),
both after `test`. Triggers: push to `main` and every pull request
(`ci.yml:3-6`). The integration test is not run in CI.
