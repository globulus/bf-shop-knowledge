# FR-0002 — Delivery note in the web shop

## User story

As a customer of the web shop, I want to write an optional delivery note in the
order form and see in my order list which orders have one, so that I can give
delivery instructions without emailing support.

## Context

> "An optional note when placing an order, in both the web order form and the
> mobile app's order screen. Max 280 characters (the warehouse label printer cuts
> off after that)." — LIN-GTB-2

> "The order list on web shows a small note icon for orders that have one." —
> LIN-GTB-2

The issue is in English, so no translation is needed.

The note is stored and validated by orders-service (FR-0001); the web shop takes
the change to the orders API from orders-service's updated OpenAPI spec. The
field's limit in the form follows DEC-0003 and counts the same unit as
orders-service (DEC-0008); what the form does when orders-service still
rejects the note follows DEC-0009; the icon in the order list follows DEC-0005.

## Acceptance criteria

### AC-1 — Order placed with a note

- **Given** a customer fills in the web order form and writes a delivery note
- **When** they place the order
- **Then** the order is placed with that note, and fetching the order from
  orders-service returns it (FR-0001.AC-1)

### AC-2 — The note is optional

- **Given** a customer fills in the web order form and leaves the note empty
- **When** they place the order
- **Then** the order is placed as before, without a note

### AC-3 — At most 280 characters

- **Given** the web order form
- **When** a customer types or pastes more than 280 characters into the note,
  counted as orders-service counts them (Unicode code points after trimming, a
  Windows line break as one character; DEC-0001, DEC-0008)
- **Then** the field holds only the first 280 characters, and the order can be
  placed with them (DEC-0003). The cut never splits a character made of
  several code points: a grapheme cluster that would cross the 280th code
  point is left out whole. Whitespace at the start or end is kept in the field
  while the customer types and counts towards the cut as typed; it is trimmed
  before the note is sent, so the sent note is never longer than 280 code
  points after trimming (F-01 of the critic, accepted by the maintainer)

### AC-4 — Note icon in the order list

- **Given** a customer's order list on the web with one order that has a note
  and one that has none
- **When** the list is shown
- **Then** the order with a note shows a note icon with a localized accessible
  label saying it has a delivery note, the order without one shows no icon, and
  the list does not show the note's text (DEC-0005)

### AC-5 — The note cannot be edited

- **Given** a placed order with a note
- **When** the customer views their orders on the web
- **Then** the web shop offers no way to change the note (DEC-0004)

### AC-6 — orders-service rejects the note

- **Given** a customer has filled in the web order form with a note that
  orders-service rejects (a validation error naming the note, HTTP 400,
  FR-0001.AC-3)
- **When** they place the order
- **Then** no order is placed, the form shows the validation error at the note
  field in the user's language, and everything the customer entered, the note
  included, stays in the form so they can shorten the note and place the
  order again (DEC-0009)

## Examples

No calculation.

## Out of scope

- Showing the note in the confirmation email (LIN-GTB-2).
- Showing the note's text in the web order list (DEC-0005).
- A character counter in the form (DEC-0003).
