# FR-0001 — Delivery note on an order (orders-service)

## User story

As a customer, I want to add an optional free-text delivery note when I place
an order, so that the warehouse knows how to deliver it (for example, to leave
it with a neighbour) without my emailing support.

## Context

Customers email support after ordering with delivery instructions. The client
wants a note stored on the order, which the customer fills in when placing it
and which the warehouse sees:

> "We want a free-text note on the order that the customer can fill in when they
> place it, and that the warehouse sees." — LIN-GTB-2

> "Max 280 characters (the warehouse label printer cuts off after that)." — LIN-GTB-2

> "The note is stored with the order and comes back when you fetch the order." — LIN-GTB-2

> "The note can't be changed after the order is placed. If they want to change it
> they can email support like today." — LIN-GTB-2

> "Backend first, then web and mobile can go in parallel once the spec is
> updated." — LIN-GTB-2

The issue is in English, so no translation is needed.

This requirement covers orders-service and its OpenAPI spec; the web shop
(FR-0002) and the app (FR-0003) build on it. Points the issue leaves open are
settled by decisions the client may still change:

- how the 280 characters are counted and what happens above the limit:
  DEC-0001 (confirmation asked in Q-0002)
- whitespace, empty notes and orders without a note: DEC-0002
- what "can't be changed" means for the API: DEC-0004
- how the warehouse sees the note: DEC-0007 (confirmation asked in Q-0001)

The note's code name is `deliveryNote` (see the glossary).

## Acceptance criteria

### AC-1 — Order placed with a note

- **Given** a customer places an order with a delivery note of 1 to 280
  characters
- **When** orders-service creates the order
- **Then** fetching that order, alone or in the order list, returns the same
  note text (trimmed as DEC-0002 says) in `deliveryNote`

### AC-2 — The note is optional

- **Given** a customer places an order without a note, with an empty note, or
  with a note of only whitespace
- **When** orders-service creates the order
- **Then** the order is created and fetching it returns `deliveryNote` as
  `null` (DEC-0002)

### AC-3 — 280-character limit

- **Given** a customer places an order with a note of 281 or more characters
  after trimming, counted as DEC-0001 says
- **When** orders-service receives the order
- **Then** it answers with a validation error (HTTP 400) naming the note, and
  no order is created; a note of exactly 280 characters is accepted

### AC-4 — The note cannot be changed

- **Given** an order that was placed with a note
- **When** any order operation orders-service offers runs on it afterwards,
  such as cancelling it
- **Then** the order's note is still exactly as it was placed, and
  orders-service has no operation that sets or changes the note of an
  existing order (DEC-0004)

### AC-5 — Older orders

- **Given** an order placed before the delivery note existed
- **When** it is fetched
- **Then** it is returned as before, with `deliveryNote` as `null` (DEC-0002)

### AC-6 — The API spec describes the note

- **Given** orders-service's published OpenAPI spec
- **When** it is read
- **Then** it describes `deliveryNote` as an optional string of at most 280
  characters on placing an order, and as a nullable string on the order
  returned when fetching orders

## Examples

| Note as sent | Length after trimming | Result |
|---|---|---|
| (no note) | — | Order created, `deliveryNote` is `null` |
| `"   "` | 0 | Order created, `deliveryNote` is `null` |
| `"  Please leave it with the neighbour at no. 12  "` | 44 | Order created, `deliveryNote` is `"Please leave it with the neighbour at no. 12"` |
| 280 × `"a"` | 280 | Order created, note stored as sent |
| 281 × `"a"` | 281 | HTTP 400, no order created |
| `"Ring twice"` + line break + `"Back door"` | 20 | Order created, note stored with its line break |
| 280 × `"č"` | 280 | Order created (characters, not bytes, are counted) |

## Out of scope

- Showing the note in the confirmation email: "Out of scope: showing the note
  in the confirmation email (notifications aren't wired up yet anyway)." —
  LIN-GTB-2
- Changing the note after the order is placed; customers email support as
  today (LIN-GTB-2).
- A warehouse screen, label printing or any other warehouse integration
  (DEC-0007).
