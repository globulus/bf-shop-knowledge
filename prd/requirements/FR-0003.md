# FR-0003 — Delivery note in the mobile app

## User story

As a customer using the app, I want to write an optional delivery note on the
order screen and see it on my order in My orders, so that I can give delivery
instructions without emailing support.

## Context

> "An optional note when placing an order, in both the web order form and the
> mobile app's order screen. Max 280 characters (the warehouse label printer cuts
> off after that)." — LIN-GTB-2

> "Mobile can show it on the order in My orders." — LIN-GTB-2

The issue is in English, so no translation is needed.

The note is stored and validated by orders-service (FR-0001); the app takes the
change to the orders API from orders-service's updated OpenAPI spec. The
issue leaves open whether the app must show the note; DEC-0006 settles that it
shows the full note on the order in My orders. The field's limit follows
DEC-0003 and counts the same unit as orders-service (DEC-0008); what the
order screen does when orders-service still rejects the note follows
DEC-0009.

## Acceptance criteria

### AC-1 — Order placed with a note

- **Given** a customer fills in the app's order screen and writes a delivery
  note
- **When** they place the order
- **Then** the order is placed with that note, and fetching the order from
  orders-service returns it (FR-0001.AC-1)

### AC-2 — The note is optional

- **Given** a customer fills in the app's order screen and leaves the note
  empty
- **When** they place the order
- **Then** the order is placed as before, without a note

### AC-3 — At most 280 characters

- **Given** the app's order screen
- **When** a customer types or pastes more than 280 characters into the note,
  counted as orders-service counts them (Unicode code points after trimming, a
  Windows line break as one character; DEC-0001, DEC-0008), not as grapheme
  clusters
- **Then** the field holds only the first 280 characters, and the order can be
  placed with them (DEC-0003)

### AC-4 — Note shown in My orders

- **Given** a customer's My orders with one order that has a note and one that
  has none
- **When** the customer looks at those orders
- **Then** the order with a note shows the note's full text, and the order
  without one shows no note (DEC-0006)

### AC-5 — The note cannot be edited

- **Given** a placed order with a note
- **When** the customer views it in My orders
- **Then** the app offers no way to change the note (DEC-0004)

### AC-6 — orders-service rejects the note

- **Given** a customer has filled in the app's order screen with a note that
  orders-service rejects (a validation error naming the note, HTTP 400,
  FR-0001.AC-3)
- **When** they place the order
- **Then** no order is placed, the order screen shows the validation error at
  the note field in the user's language, and everything the customer entered,
  the note included, stays on the screen so they can shorten the note and
  place the order again (DEC-0009)

No calculation.

## Out of scope

- Showing the note in the confirmation email (LIN-GTB-2).
- A character counter on the order screen (DEC-0003).
